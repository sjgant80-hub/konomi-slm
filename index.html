KONOMI · neurosymbolic verified knowledge engine

It proves what it says,
or it abstains.

This is not an LLM — and that's the point. A model proposes, but only rules that predict unseen data are kept, so the engine proves what it says and says "I don't know" when it can't. Knowledge lives in a verified, readable, compressed pattern-library — each rule predicted held-out cases it never saw, or it was cut — not smeared across opaque weights, so it can't be shrunk away and it doesn't hallucinate. It grows by adding verified rules, not by retraining. The whole knowledge-base compresses to a seed, and it runs entirely in this browser.

In plain words. You give it past cases that already have an outcome — rows in a spreadsheet: a shop visit and whether it bought, a set of readings and whether it was critical. It grows a handful of rules you can read, and it keeps them only if they correctly rank cases it was never shown. Then, for a new case, it either answers from those rules and hands you a receipt anyone can re-check, or — if the case is unlike anything it checked — it says "I won't guess."

It runs in this browser tab. Nothing you type or grow here is sent anywhere.

In field terms: neurosymbolic AI (a neural proposer + symbolic verified rules) · selective prediction (it abstains) · evolutionary program search (the FunSearch / AlphaEvolve family — propose, test on held-out, keep only winners) · compression-as-intelligence (the shortest model that predicts the data). Fused into one owned, CPU-scale, multi-domain system. We don't compete on "is the model big enough" — we stand on "is the answer verified."

In this tab, no install, no sign-in. Every number you see is computed by the same code the tests and the mutation gate check.

  1. Grow the library. Press Grow the library in section 1. Each tiny seed grows a pattern on its training cases and is graded on cases held back; only patterns that clear the gate stay. The cards show each one's held-out score and its seed size in bytes.
  2. Ask it a real case. In section 3 a real held-out case is already filled in. Press Ask: you get an answer, how well the case fits the pattern, and a receipt.
  3. Check the receipt. Open the receipt, press verify receipt (genuine), then tamper one field (caught). That is how anyone downstream re-checks an answer.
  4. Watch it refuse. Press Make it out-of-distribution, then Ask. It abstains instead of guessing.
  5. Climb the ladder (optional). In section 2, Grow tier 2 from tier 1 adds new domains and deepens old ones; a domain is never allowed to get worse.
  6. Keep it. Section 4 downloads the library (a text file of seeds) and the last receipt. They are yours, offline.
  7. Read the head-to-head. The multiplier test pits the shop pattern against bigger raw language models on real sessions it never saw — sealed before it ran, kept whatever it showed.
  8. Run it on your own data. Clone the repo and run node tools/your-brain.mjs <folder of CSVs> — each file becomes an organ only if it predicts its own held-out rows (your-brain).

How to re-check it yourself

Clone the repo and run node tools/check-multiplier.mjs: it re-derives the sample and the three Konomi arms from the data, checks every recorded prompt is the sealed prompt, re-parses every recorded reply and re-computes every claim, and fails on any difference. To re-ask the models, install Ollama with the sealed model digests and run node tools/run-multiplier.mjs — a model's replies are not reproducible byte for byte, which is why the receipt keeps every one.

Step by step, in the code
  1. buildPattern() in konomi-slm.mjs loads a domain, makes a seed, and germinate() (the vendored seed-library ribosome) grows and grades it: a short search for rules on the training rows, scored by AUC on the held-out rows.
  2. fit() turns the champion into a scorecard of rules; operatingThreshold() sets the cut-off from the training rows' base rate; fingerprint() records each feature's spread on the training rows.
  3. buildLibrary() keeps a pattern only if its held-out AUC is at or above GATE_AUC; anything else is listed as cut, with why.
  4. route() scores a new case against each pattern with membership() — 1 inside the middle half of the training spread, decaying outside — and answer() abstains below ROUTE_MIN.
  5. Above the line, scoreInput() adds the weights of the rules that fire, compares to the threshold, and answer() hashes the record into the receipt; verifyReceipt() re-hashes it.
  6. growTier() in grow-tier.mjs climbs the ladder: each old domain is deepened from its champion and kept only if it does not get worse on held-out; new domains enter only through the gate.

Adoption — what it does for a team, and how to roll it out

Any decision your team makes over and over from records, where the outcome is later known: will this visit buy, is this reading critical, will this machine fail, is this transaction risky, will this customer leave. The engine answers the cases it can prove, with a receipt, and hands the rest to a person.

  1. Pick one decision. One question with a yes/no outcome you already record, and enough history to hold some back.
  2. Export the history. A CSV of past cases with their outcome column (two values, such as bought / did not). It stays on your machine. The tool picks the outcome column itself — a two-valued column named like an outcome, otherwise the last two-valued one; to choose it, put a brain.config.json beside the files: {"targets": {"visits.csv": "Revenue"}}.
  3. Grow it where it will run. node tools/your-brain.mjs data/ grows an organ per file and keeps it only if it predicts that file's held-out rows; a file with no signal is refused, with the reason in the receipts.
  4. Read what it kept. Each organ prints as a short pattern book your team can challenge in plain language. If a rule looks wrong to the people who do the work, find out why before going further.
  5. Plug it in. From any Node script, import answer() from konomi-slm.mjs and pass it the library and a case as named numbers; it returns VERIFIED with the answer and its receipt, or ABSTAIN with the reason. A browser page can do the same, as this one does. There is no server to run.
  6. Run it in the shadow. Let it answer alongside the team for a period you choose, and compare its answers and its abstains with what people decided.
  7. Go live on what it answers. Verified answers go straight through with their receipt; abstains route to people as today. Log every receipt — they re-check offline.
  8. Grow it. Add files and decisions; re-grow as new months arrive. The ladder keeps a domain only if it does not get worse on held-out.

    • No accounts, no tracking. No sign-in, no cookies, no analytics on this page.

    White paper — the inversion, in short

    The problem

    A language model keeps what it knows smeared across billions of weights. You cannot read it, you cannot check which part produced an answer, and when it does not know it still answers. Shrinking it to run cheaply loses knowledge, because the weights are the knowledge. Renting it means your decisions depend on someone else's model, prices and terms.

    The inversion

    Put the knowledge somewhere you can read and check — a library of small patterns, each a few rules with weights — and let a model, if one is used at all, only propose. A pattern enters the library only if it ranks cases it was never shown at or above a published gate. The library stores each pattern as a short seed that re-grows it exactly, so the whole knowledge base is a text file.

    Answer or abstain

    For a new case, a router measures how far each number sits from where the pattern's grow cases sat. If the case fits, the rules answer and the answer is hashed into a receipt anyone can re-check. If it does not fit, the engine abstains. Refusing the unanswerable is not a weakness to hide: on a mixed stream of answerable and unanswerable cases it is where the advantage over an always-guess model comes from. The measured report, node tools/run.mjs, scores that mixed stream against an always-guess baseline, and CI runs it on every push.

    Growth without retraining

    The library grows by adding verified patterns and deepening old ones — never by retraining weights. Each rung of the ladder starts from the last rung's champions and keeps a domain only if it holds or beats the last rung on held-out cases, so the record can only improve. It runs on an ordinary CPU.

    Where it sits in the field

    Neurosymbolic AI (a neural proposer with symbolic, checked rules), selective prediction (it abstains), evolutionary program search in the FunSearch / AlphaEvolve family (propose, test on held-out, keep only winners), and minimum description length (the shortest model that predicts the data). This is those four, fused into one owned system.

    What it does not do

    It does not write free text or hold a conversation. It works on structured, repeated decisions with a known outcome to learn from. Its claims are about the domains it has verified patterns for, and the measured results on this page — including the ones that did not come out in its favour.
